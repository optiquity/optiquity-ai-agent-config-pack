Description:
  **Problem:** the migrator has NO auto-merge. On any file both the project and the pack changed (`real-merge-required`), `_cp_strategy_text` saves the project's copy as a `.v10-customized` sidecar, drops the pack v11 version live, and defers to the user (accept / keep / hand-merge). BD-282 (calm pause), BD-283 (interactive prompts), and BD-286 (pre-fold guide) all refined the DEFER experience, but NONE of them MERGE — a customizing project cannot obtain a file that combines the pack's v11 update with its own customizations without hand-work. Verified in code: no `git merge-file` / `diff3` / auto-merge anywhere in the migrator; the `real-merge-required` arm is a bare `cp ours sidecar`.
  **Goal — two layers, fully hands-off:**
  1. **Tool 3-way merge.** At `real-merge-required`, run a real BASE/OURS/THEIRS merge (`git merge-file` / `diff3` — the migrator already holds all three: BASE via `git show v10:<pack-relpath>`, OURS live, THEIRS the pack template) and write the MERGED result live. Auto-combines every change where the project and the pack touched DIFFERENT lines (the common case → clean, no effort). Standard `<<<<<<<` / `>>>>>>>` markers remain ONLY where both edited the SAME lines.
  2. **Trinity smart-merge.** For the trinity, do better than a line merge: adopt the v11 pack body AND auto-place the project's additions (`diff BASE OURS`) into the `<!-- BEGIN/END project-owned -->` marker slot — no hand-fold (this AUTOMATES BD-286's pre-reconcile). Usually zero conflicts.
  3. **Agent resolution of same-line overlaps.** For any file still carrying conflict markers after the tool merge, an AI agent reads BASE/OURS/THEIRS + the marked hunks and writes a sensible combined file → ZERO conflict markers in the final output. Fully hands-off.
  **The KEY architectural question (architect decides, evidence-based):** how the agent-resolution layer is invoked from a CLI-agnostic bash migrator. Candidate models — (a) the migrator shells out to a CLI (`claude` / `codex` / `gemini`): breaks the CLI-agnostic-bash contract + needs auth/cost/availability handled INSIDE the migrator; (b) the migrator (bash) produces the tool-merged state (files with standard conflict markers) and a SEPARATE skill / PM-chat step resolves the markers: keeps the migrator pure bash and the AI step a distinct, optional layer (fits "the pack's primary user is an AI-agent-driven PM chat"). Cross-CLI (Claude / Codex / Antigravity) must be handled; the safe non-interactive/CI default must never silently ship a wrong merge.
  **Relationship to BD-282/283/286:** SUPERSEDES the accept/keep/defer premise for a customizing project — the interactive loop gains a real `[m] merge` that actually merges. BD-286's pre-reconcile guide becomes an OPTIONAL pause-free optimization (auto-merge removes the NEED to pre-fold). The existing accept/keep/defer options remain for a user who wants wholesale one-side selection.
  **Honesty:** where the project and the pack edited the identical lines, no tool can guess which wins — the agent layer resolves those; without it, standard conflict markers are the honest floor. The agent layer's output is itself reviewable (the pre-merge sidecar + the tool-merge markers remain recoverable).
Acceptance criteria: a customizing project migrates v10→v11 and every conflicting file (trinity + generic docs) ends FULLY MERGED — the pack's v11 changes AND the project's customizations both present — with ZERO conflict markers in the final output, no accept/keep/defer choice required, and no hand-fold; the tool-merge layer is a real BASE/OURS/THEIRS merge (`git merge-file` / `diff3`); the trinity smart-merge auto-places project additions into the marker slot; the agent-resolution layer resolves same-line overlaps to zero markers; a safe non-interactive / `--no-interactive` / CI default is preserved (never silently ships a wrong merge — architect defines the fallback, e.g. leave markers + pause); the pre-merge state is recoverable (sidecar/backup retained); cross-CLI (Claude / Codex / Antigravity) invocation is handled; a demo/test proves a customized file merges to ZERO markers end-to-end; full migration + tracker battery + `validate-pack` (both jobs + `PACK_VALIDATE_DEEP=1`) green.
