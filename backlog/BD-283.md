Description:
  **Problem:** the v10→v11 migration is fully non-interactive. On a customization conflict it prints a copy-paste menu, `migrator_pause`s (exit 0), and requires the user to hand-run remove/rename/touch commands per file + re-invoke `--resume` (`apply.sh` pause block + `resume.sh`). BD-281/282 made the pause honest + calm, but the reconciliation is still a manual multi-hop — the "cumbersome" core the user flagged.
  **Prior art (de-risks this):** `scripts/lib/tracker-init.sh` already ships a complete, TESTED, TTY-detecting interactive idiom (`--no-interactive`, `[[ -t 0 ]]` auto-detect, a force-interactive env test-seam, stdin-piped test harness). Interactive bash prompting is a SOLVED, in-repo pattern — this applies it to the migrator, not a new capability.
  **Goal:** at the pause, when interactive is available, offer an in-process prompt loop — per conflicting file, show a compact live-vs-sidecar summary and prompt `[1] accept pack [2] keep yours [3] merge later [s] skip [q] quit`; apply the choice in-process (remove / rename / mark `.resolved`), record it; after the loop, if all resolved auto-continue S4–S6 (no `--resume`); if any deferred, fall back to today's pause+resume contract for exactly those files.
  **Graceful degradation (load-bearing):** tri-state per tracker-init — `--interactive` forces the loop; `--no-interactive` forces today's print-menu-and-pause; default = stdin-is-a-TTY → interactive, non-TTY (CI / piped / the `dry-run-migration.sh` child) → today's non-interactive pause byte-for-byte. Nothing regresses for CI/automation/audit.
  **Honesty (BD-282 alignment):** the loop chooses only among the three BD-282-blessed actions; a genuine line-by-line merge still defers to hand-edit + resume (option 3). The layer removes the TRANSCRIPTION burden, not the DECISION burden — the "no universally-safe auto-resolution" invariant holds.
  **Cross-CLI:** the migrator is CLI-agnostic bash (not a per-CLI agent) — pure `read` prompting, NO trinity parity edit.
Acceptance criteria: interactive mode (`--interactive` / TTY-auto) walks each conflict, applies the choice in-process, and completes S4–S6 without a separate `--resume`; `--no-interactive` and the non-TTY default preserve the current copy-paste + `--resume` flow byte-for-byte (CI/automation unchanged); a failed/EOF read never crashes under `set -euo pipefail` (the tracker-init default-on-fail idiom); the new interactive test (stdin-piped answers + force-interactive seam) asserts each file reaches the right end-state and S4–S6 ran; `MIGRATION-v10-to-v11.md` updated in lock-step; full migration + tracker-migrate battery + `validate-pack` (both jobs + `PACK_VALIDATE_DEEP=1`) green; the migration control-flow/exit-codes for the non-interactive path unchanged.
