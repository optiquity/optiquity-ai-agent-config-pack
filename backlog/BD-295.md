**BD-295 — `init-project.sh --update` has no baseline: it classifies every file `project-shadows-new-pack` without comparing, is not idempotent, and never reaches the prompts or skills trees — so no client can safely take any pack release**
Type: bug — update path / customization-preservation classifier (client-facing mechanism; measured, not inferred).
Status: Open
Target: v11.0
Blockers: None. The defect is measured at its call sites and reproduced by execution.
Unblocks: every client's ability to take any pack release without hand-reconciling its whole tree — and the remediation criteria of the two client-install BDs, which both depend on `--update` behaving.
File/Symbol: `scripts/init-project.sh` (`cmd_update` — the `customization_preserve "" …` call sites and the file-set map that omits the prompts + skills trees); `scripts/lib/three-way.sh` (`three_way_classify` — the `project-shadows-new-pack` branch that returns without comparing, and its header contract); `scripts/lib/customization-preserve.sh` (the disposition routing + sidecar emission); `scripts/tests/` (idempotence + coverage regression tests) — docs-researcher census completes the set.
Description:
  Measured at pack HEAD, and reproduced by running the tool: `cmd_update` passes an EMPTY BASE to `customization_preserve` at every call site, documented in its own comment ("BASE is left empty (no prior pack baseline available offline…)"). With no BASE, `three_way_classify` takes the `base absent, ours present, theirs present` branch and returns `project-shadows-new-pack` **unconditionally — it never compares OURS to THEIRS.** Its own header contract says that disposition should "classify by ours-vs-theirs and let caller route … if they differ", so the code contradicts the documented contract: an untouched file and a heavily customized file are indistinguishable to it.
  **Measured consequences.** (1) NOT IDEMPOTENT: a second `--update` against an UNCHANGED pack produced 105 of 110 files classified needs-reconciliation with 105 sidecars written, including a file proven byte-identical by `cmp -s`. A client who runs the supported update command twice must hand-resolve its entire tree. (2) COVERAGE GAPS: the update file-set reaches ZERO files under `docs/pack/prompts/` and the skills trees — a simulated prompt-side fix did not land while doc and agent fixes did. (3) The failure is arrival-path-independent: it is not specific to clients that arrived by migration, so every client on every future release is affected.
  This is the precondition for the two client-install BDs: their acceptance criteria require an already-migrated client to take fixes via `--update` with zero new sidecars and nothing customized touched, which is unreachable while the classifier cannot tell an unmodified file from a customized one.
Acceptance criteria: `three_way_classify` honors its own documented contract — with BASE absent it compares OURS to THEIRS and distinguishes identical from divergent, proven by a unit test that BITES on the current behavior; `--update` is IDEMPOTENT, proven by running it twice against an unchanged pack on a real-shaped client tree and observing zero sidecars and zero reconciliation findings on the second run; a genuinely customized file still routes to reconciliation (the fix must not silently overwrite client work — proven by a test in the opposite direction); the update file-set reaches every client-installed surface, with the covered set derived from the install map rather than a hand list, and prompts + skills coverage proven by a simulated fix landing in each; the classifier's header contract and the `cmd_update` comment are reconciled to the shipped behavior; full CI battery green.
References: measured during the BD-293/BD-294 stage-1 census (report in the pack handoff tree). The two client-install BDs consume this entry's fix as their remediation vehicle; sequence this one first or in lock-step with them.
Position: v11.0 — launch-gating, and arguably ahead of the sibling entries: shipping a release whose own update command cannot be run twice safely is a worse client experience than the defects that surfaced it. Runs the LARGE deterministic pipeline jointly with the install-fidelity entry (same machinery, same architect).
