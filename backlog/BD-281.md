**BD-281 — Migrator `--dry-run` pause-prediction is false: the dry-run dispatch legs record a blind `pack-update-applied` instead of classifying, so Gate-1's "will run end-to-end without pausing" is unreliable — run the real classifier read-only in dry-run**
Type: bug — migrator framework (v10→v11 dispatch-stage dry-run report accuracy; launch-relevant migration UX, NOT a data-safety defect).
Status: Resolved
Target: v11.0 (surfaced during BD-205 W3 real-content migration testbed 2026-08-10; the migration itself is SAFE + resumable — proven end-to-end on real client content: Gate 2 PASS, monoliths decomposed + deleted, resume exit 0). This is a dry-run REPORT-accuracy defect. Lands in v11.0 per no-deferral unless the user defers.
Blockers: None.
Unblocks: a truthful dry-run pre-flight — a user who runs `--dry-run` and reads the pause prediction can trust it.
File/Symbol: `scripts/lib/migrator-manifest.sh` — the two `--dry-run` dispatch legs `_manifest_dispatch_transform()` (~L288-292) and `_manifest_sweep_one_dir()` (~L511-514), which record a BLIND `pack-update-applied` disposition instead of running the real classifier; `scripts/lib/migrator-stages.sh` `_stage_dispatch()` (dry-run scratch-dir lifecycle for the fix); `scripts/tests/test-migrate-v10-to-v11-dry-run.sh` (new dry-run-predicts-pause + prediction-bites test group); `scripts/lib/migrate-v10-to-v11/gate-1-dry-run-summary.sh` (~L72-76 — the faithful reporter fed the bad data; verify-only, expected byte-unchanged). NOT `apply.sh` — its `_migrator_is_dryrun` early-return is correct and off the dry-run report path (a plain `--dry-run` never installs that hook).
Description:
  **Problem (observed, BD-205 W3, real client content, 2026-08-10):** `--dry-run` reported Gate-1 to the effect of "conflicts: 0 — `--apply` will run end-to-end without pausing." The subsequent `--apply` on the same tree detected 5 customizations (CLAUDE / AGENTS / GEMINI / PM-CHAT / PACK-FEEDBACK `.v10-customized` sidecars), wrote sidecars, and PAUSED for reconciliation; `--resume` then completed cleanly into a valid v11 tree. The dry-run's pause prediction was therefore FALSE.
  **Root cause (measured — the design record is the BD-281 architecture doc §2):** the DISPATCH stage, in `--dry-run` mode, records a BLIND `pack-update-applied` disposition for every file instead of running the real `customization_preserve` classifier — `scripts/lib/migrator-manifest.sh` `_manifest_dispatch_transform()` (~L288-292) and `_manifest_sweep_one_dir()` (~L511-514), each with the (inverted) comment "Still record a finding so the dry-run report is truthful". So `dispositions.tsv` can NEVER contain a `customization-detected-needs-reconciliation` row in dry-run, and Gate-1 (`gate-1-dry-run-summary.sh:75`) faithfully counts zero and prints the false all-clear. Gate-1 is CORRECT — it was fed non-truthful data. (The `apply.sh` `migrate_v10_to_v11_apply_after_dispatch()` early-return first suspected for this is NOT the cause: a plain `--dry-run` never installs that post-dispatch hook; the early-return is correct for the rare combined `--dry-run --apply` mode.)
  **Not a data-safety defect:** the `--apply` / `--resume` path is correct — it detects customizations, writes sidecars, pauses, and resumes into a valid v11 tree. Proven end-to-end on real client content in BD-205 W3 (Gate 2 PASS; 113 backlog + 55 changelog entries decomposed; v10 monoliths deleted after verified decompose per `fail-loud-delete-old-source`; `resume exit: 0`). The defect is confined to the dry-run's FALSE PROMISE, which erodes trust in the dry-run as a pre-flight.
  **Goal:** the dry-run's pause prediction is TRUTHFUL — it accurately reports "would pause on N sidecar(s): <list>"; never a false "will run end-to-end without pausing."
  **Adopted design (BD-281 architecture doc §4 — Approach B):** in the two dry-run dispatch legs, run the PROVEN real `customization_preserve` with `dest` redirected into a throwaway `mktemp -d` scratch dir (created + `rm -rf`'d in `_stage_dispatch`, dry-run only). Same code as `--apply` ⇒ the predicted pause set == the apply pause set BY CONSTRUCTION (truthful, bites — not a proxy); every strategy write lands in scratch / state-dir `diffs/` / `mktemp`, so the project tree is never mutated; `apply.sh` / `resume.sh` / the gates / the strategy files stay byte-unchanged. A bounded post-pass normalizes the report's scratch sidecar path back to the real target path (cosmetic). Rejected: Approach A (refactor the proven strategies — regression risk + a second implementation that can DRIFT from apply), Approach C honest-floor (Gate-1 states the prediction is unavailable — no real preflight; retained only as the fallback if B is vetoed), whole-tree scratch clone (heavy; the framework can't redirect the target mid-run).
  **Provenance:** surfaced by the BD-205 W3 real-content migration testbed (2026-08-10); pre-existing, NOT BD-205-caused; launch-relevant (migration UX at v11.0 launch).
Acceptance criteria: a `--dry-run` against a tree with customizations reports the pause accurately (count + file list) — never a false "will run end-to-end without pausing"; the `--apply` / `--resume` behavior is UNCHANGED (still detects, pauses, resumes; NO sidecar or tree mutation during dry-run — snapshot-before == snapshot-after); a new prediction-bites test asserts dry-run predicted-count == apply actual-paused-count; the no-customization path still reports the truthful all-clear; `validate-pack` green; the full migration battery (both jobs + `PACK_VALIDATE_DEEP=1` + the migration + tracker-migrate suites) passes.
