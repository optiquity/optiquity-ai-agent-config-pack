SSOT / MIRROR MODEL (settled, user 2026-06-05): the per-entry tree is the SOLE flat representation — there is NO monolith, ever. BD-204 therefore RETIRES-or-REPOINTS the LOCKED monolith machinery to the no-monolith reality: the `tracker.toml [mirror]` config table + Check 29 staleness guard (compat-report C1), and the forward read-side input + reverse emit target + agent-read + header-snapshot sites (C2/C3/C4/C7b), all target the per-entry TREE — never `pack-ops/BACKLOG.md`. For the tracker to be a TRUE SSOT the provider must support FULL CRUD — the built forward path is create-only (`provider_update` unwired); BD-204 completes the CRUD surface. Identity keys on the `pack-id` marker, NEVER on GH Issue numbers (non-portable, non-stable across delete/recreate).
GENERALIZABLE (HARD design property, user 2026-06-05): the Mode-2↔3 machinery is parameterized by tree/surface, NOT hard-wired to the pack backlog. BD-204 implements ONLY the pack-backlog instance (pack-only), but keeps the shared layer free of pack-specifics so future trees + the project side (BD-207, the `_tmr_emit_backlog` client branch) reuse the same design unchanged.
