**BD-228 — Push-time manifest regeneration method + enforcing check (retire the per-commit RC9 prose obligation)**
Type: feat — build/release tooling + CI check. Replace the per-commit `regenerate-manifest-v11-surface` (RC9) prose obligation with an IMPLEMENTED push-time method + a machine-enforced check. The manifest (`test-fixtures/manifest.txt`) is regenerated ONLY at push, and ONLY when a fixture-input file changed. Opened 2026-06-17 (user direction), emerged from the BD-221 cluster's parallel-commit manifest bottleneck.
Status: Open
Target: v11.0 — small, self-contained; removes an honor-system rule that produced 2 documented CI-red incidents. No hard blocker; implements in parallel with the remaining BD-221 cluster work. The BD-221 cluster push is the method's first live exercise (dogfood), or does a one-time regen if BD-228 is not yet landed at push.
Blockers: none.
Unblocks: decoupled parallel commits no longer serialize on the single shared manifest (work drives concurrency, not the generated artifact); eliminates wasteful per-commit `build.sh --all --clean` rebuilds (N throwaway intermediate manifests across N commits); replaces the honor-system RC9 prose with authority in code (tool + check). Also corrects the current rule's over-trigger: measurement proved `pack-ops/` is NOT a fixture input, yet RC9's 4-dir trigger forces a needless empty rebuild on every `pack-ops/` commit.
File/Symbol:
  - `scripts/manifest-sync.sh` (NEW) — pack-side build/release tool the orchestrator runs immediately before `git push`. Diffs the unpushed range (`@{upstream}..HEAD` with fallbacks); runs `build.sh --all --clean` exactly once IFF a fixture-input path changed; complete no-op otherwise. Never commits/pushes — signals via exit code (`10`=MANIFEST-CHANGED, `0`=SKIP/NOOP, `1`=error). Commit-count-agnostic (set test over the union diff). Does NOT ship to clients (not in the install-map; not in `_SANCTIONED_PACK_SIDE_SHIPPED`).
  - the fixture-input predicate (single source of truth — inline in the tool or a small shared `scripts/lib/manifest-inputs.sh`): the EXACT input set — `project-template/` + `scripts/` (minus tests + the tool) + `test-fixtures/build.sh` + exactly `supporting-docs/{METHODOLOGY,INSTALL-PROCEDURES}.md`. Drift-proofed by the `build.sh --verify` backstop (a missed new input → CI RED, never silently stale).
  - `scripts/validate-pack.py` — NEW Check 62 (manifest structural well-formedness: row count == 6, names == `_fixture_names_from_build_sh()`, each SHA `^[0-9a-f]{40}$`/sentinel). Cheap pure file-read+regex (safe under `ci-check-runtime-compounding`). The authoritative SHA-correctness gate remains the existing CI `build.sh --verify` (UNCHANGED).
  - `scripts/tests/manifest-method-test.sh` (NEW) — self-provisioned scratch-clone test of the method (positive/negative/idempotency/range/predicate-drift); Check 62 per-check test per the wiring convention.
  - RC9 prose removal across 6 surfaces: trinity ×3 (`CLAUDE.md`/`AGENTS.md`/`GEMINI.md` — per-commit bullet → one-line pointer at the tool+check, lock-step); `pack-ops/PACK-MEMORY-RATIONALE.md` (rewrite HOW-to-apply, keep the incident WHY, fix the stale `HELP-FRAGMENT-TRACKER.md`-is-an-input claim); `pack-ops/PACK-CHAT.md` propagation row; the out-of-repo memory cache `feedback_manifest_regen_on_v11_surface.md` (Pack-Chat-direct).
Description:
  **Problem:** `regenerate-manifest-v11-surface` (RC9) is a PER-COMMIT prose obligation — any commit touching a v11-surface dir must regenerate + stage the manifest. This (a) is WASTEFUL (N fixture-touching commits → N full rebuilds producing throwaway intermediate manifests, immediately superseded), (b) SERIALIZES otherwise-decoupled parallel commits on one shared cumulative file (the generated artifact dictates concurrency), and (c) is honor-system prose enforced by no implemented check (it caused 2 documented CI-red incidents). The manifest is a deterministic build artifact (fixtures commit with pinned identity → identical inputs ⇒ identical SHA), so it can only change when a fixture-input changes, and CI already verifies it only at the pushed HEAD.
  **Solution (user-directed: a designed + implemented METHOD + CHECK, NOT a rule/memory entry):** the manifest is regenerated ONLY at push, ONLY when expected to change, by `scripts/manifest-sync.sh`; correctness is machine-enforced by the existing `build.sh --verify` (authoritative SHA gate, unchanged) plus a new cheap structural Check 62; the per-commit RC9 prose is removed and replaced by a one-line pointer at the tool+check. Authority moves from prose to code.
  **CI-safety:** every failure path is RED (a skipped/failed regen → `build.sh --verify` MISMATCH at the pushed HEAD), never a silent stale ship — strictly stronger than the prose regime.
  **Implementation:** architect ✅ (design doc — see References) → planner → coder → bounded review/fix. Suggested grouping: C1 tool+test; C2 Check 62+test; C3 RC9 prose removal (trinity lock-step + rationale + propagation + memory cache). Self-hosting — this BD touches `scripts/`, so its own push is the method's first live exercise (run the tool; do not hand-edit the manifest).
Acceptance criteria: `manifest-sync.sh` regenerates the manifest once at push iff a fixture-input changed and is a no-op otherwise; the predicate excludes `pack-ops/`/`maintenance-docs/` (no false positives) with no false negatives (backstopped by `build.sh --verify`); Check 62 catches a malformed manifest cheaply in the always-run job; the per-commit RC9 prose obligation is removed across all 6 surfaces and replaced by the tool+check pointer; the method + check are test-covered (self-provisioned); validate-pack green; the manifest is never hand-edited.
