**BD-220 — Refactor the CI long-pole tests internally to lower the shard floor (effectiveness-preserving)**
Type: feat — CI/test-infra performance. The "candidate E" optimization surfaced (and deliberately NOT absorbed) by the BD-219 architect: shrink the wall-time of the slowest individual test scripts so the matrix-shard floor drops further. Distinct unit of work from BD-219 (which orchestrates the existing tests across shards without changing any test's internal runtime). Full pipeline (researcher → architect → planner → coder, bounded review/fix).
Status: Deferred
Target: v11.1 (user 2026-06-15) — scheduled at the END of v11.1, after the other v11.1 work.
Blockers: BD-219 (the matrix-sharding + the committed per-script weight data land first). Lowering an individual test's runtime only improves wall-time once the battery is sharded — BD-219 establishes the shard model + the measured per-script weights this BD optimizes against. Not started until BD-219 is Resolved AND the prior v11.1 backlog is complete.
Unblocks: a further `Validate Pack` wall-time reduction beyond BD-219's sharding. BD-219's 4-shard design is FLOORED by the single longest test (`migrate-gates` ≈ 94s in CI) — no shard can finish faster than its longest member. Cutting that floor lets BD-219's dynamic partition rebalance to a lower max-shard (and possibly justify a different shard count).
Description:
  **Problem:** BD-219 measured the per-script CI durations; the long poles are `scripts/tests/test-migrate-gates.sh` (~94s CI), `test-tracker-migrate-forward` (~61s), and `test-tracker-migrate-roundtrip` (~52s). Because a matrix shard cannot finish faster than its slowest member, the 94s test sets the hard floor of BD-219's sharded `tests` job (~140–160s). These scripts are slow for internal reasons (repeated full migrations / round-trips / subprocess churn per case), not because of how they are orchestrated.
  **Goal:** reduce the internal runtime of the long-pole test scripts WITHOUT reducing test coverage or effectiveness (HARD CONSTRAINT, same as BD-219 — every case still asserted; mutation-equivalent coverage). Candidate techniques for the architect to evaluate (not prescribed): share/reuse expensive setup across cases instead of rebuilding per-case; parallelize independent cases within a script; cache deterministic intermediate artifacts within a run; collapse redundant full-migration passes that assert the same invariant. Each technique must be proven effectiveness-neutral (mutation testing / before-after assertion inventory).
  **Tracker note:** `test-tracker-migrate-*` exercise the DORMANT tracker code retained + test-covered under the indefinite tracker deferral — confirm those tests still run and are worth optimizing (vs. left as-is) given the dormant status; the architect decides per-script whether to optimize or leave.
  **Scope:** internal runtime refactor of the identified long-pole `scripts/tests/*.sh` scripts; re-measure + update BD-219's `scripts/ci-shard-weights.tsv` so the dynamic partition rebalances; optionally revisit the BD-219 shard count if the floor drops enough.
  **Out of scope:** the matrix-shard orchestration / aggregation / guards (BD-219); `validate-pack --only-check` (BD-219); removing or weakening any test or check; any change to BD-197 worktree-isolation behavior.
  **Acceptance criteria (provisional — refined by research):** measurable reduction in the long-pole scripts' wall-time (record before/after) with PROVEN-unchanged effectiveness (mutation-equivalent; full assertion inventory preserved); BD-219's shard weights updated and the partition rebalanced; full CI battery green; the `ci-check-runtime-compounding` per-check runtime guards intact.
References: BD-219 (the matrix-shard model + `scripts/ci-shard-plan.py` + `scripts/ci-shard-weights.tsv` this builds on; the research's "candidate E" + the architect's out-of-scope surfacing in ARCHITECTURE-BD-219-CI-RUNTIME-OPTIMIZATION.md §0/§3); the `ci-check-runtime-compounding` Pack-memory rule; the slow scripts `scripts/tests/test-migrate-gates.sh`, `test-tracker-migrate-forward.sh`, `test-tracker-migrate-roundtrip.sh`.
