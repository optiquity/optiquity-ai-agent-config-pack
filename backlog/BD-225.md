**BD-225 — Add Graphify knowledge-graph support for Pack Chat + pack agents' own work (PACK-OPS; not shipped to clients)**
Type: feat — pack-ops tooling / agent token-efficiency. Wire the Graphify knowledge-graph tool (`graphifyy` CLI) into THIS repo so Pack Chat + the pack-* agents query a compact repo subgraph instead of re-reading the file tree — for pack self-maintenance AND the `project-template/` deliverables they maintain. Opened 2026-06-16 (user direction). All design decisions pre-adjudicated with the user (see below) → pipeline can go straight to architect/planner/coder (the design is locked).
Status: Open
Target: v11.0 (user 2026-06-16, ASAP). Orthogonal pack-ops (does NOT change what ships to clients), so not itself a launch-behavior gate, but pulled into v11.0 to accelerate pack development.
Blockers: BD-221 — the graph-first rule lands in the PACK-ROOT trinity (`CLAUDE.md`/`AGENTS.md`/`GEMINI.md`), which BD-221's C6 converts to Antigravity. So this BD is a **FAST FOLLOW-ON directly after BD-221** (lands the rule on the converted trinity; NOT folded into the BD-221 cluster). The non-trinity parts (`.graphifyignore`/`.gitignore`, hooks, pack-ops doc, build) are independent of BD-221.
Unblocks: token-efficient repo context for Pack Chat + every pack agent it spawns (the pack is doc/reference-heavy + agent-heavy — exactly Graphify's sweet spot); fewer full-tree reads per query.
Description:
  **BOUNDARY (absolute):** PACK-OPS ONLY — NOT a client deliverable. The graph INDEXES the whole repo (incl. `project-template/`, so agents working on the deliverables get context), but every setup artifact lives PACK-SIDE and nothing ships inside the config pack: the graph-first rule → PACK-ROOT trinity (NOT `project-template/` trinity); `.graphifyignore` + the `graphify-out/` gitignore line → PACK ROOT (NOT `project-template/.gitignore`); the how-to → a `pack-ops/` doc. Putting any of it in `project-template/` is a P-missed-7 boundary regression.
  **Source guide:** `dshanenyc-mac-setup/docs/graphify/REPO-QUICKSTART.md` (the portable per-repo guide; read §7 + the precedence rule). `graphifyy` is already installed on the user's machines.
  **LOCKED design decisions (user 2026-06-15/16 — pre-adjudicated; architect/planner cite verbatim, do NOT re-open):**
    - **(1) Trinity wiring = FAST FOLLOW-ON after BD-221 C6** (its own BD; not folded into the cluster). Add a `## Knowledge graph (graphify)` graph-first rule to the PACK-ROOT trinity (auto-loaded into custom pack subagents → pack-architect/coder/planner/reviewer/docs-researcher query the graph FIRST). All pack agents already have the `Bash` tool (no frontmatter change). Trinity-rule lock-step across all three pack-root files, audience-correct.
    - **(2) Build the graph AFTER `.graphifyignore` is in place** (`/graphify .`, main-session/subscription; updatable anytime).
    - **(3) Update policy = HYBRID-WITH-REMINDER (NOT ollama):** (a) Option-B **pre-commit hook running `graphify update .`** (the ZERO-TOKEN, code-only CLI — NOT `/graphify . --update`; honors `.graphifyignore`; non-staging; non-blocking/exit-0); (b) **Pack Chat runs `/graphify . --update` (the semantic pass) after doc-heavy commits** (free via the live session's subscription, high quality — the doc layer CANNOT be hooked: a headless git hook has no LLM, and the free pass needs the live Claude session = Pack Chat itself); (c) a **local non-blocking "docs changed" reminder hook** as the backstop. Baked into the pack-ops doc + Pack Chat operating rules.
    - **(4) v11.0** (ASAP).
    - **(5) Secrets-adjacency = NO concern** — the pack has no secrets and never should; only example configs; Pack Chat already reads the docs (marginal exposure ~nil).
  **IGNORE HANDLING (user-confirmed 2026-06-16):**
    - `.graphifyignore` does NOT "replace" `.gitignore`; its PRESENCE makes graphify stop CONSULTING `.gitignore` (the fallback). `.gitignore` keeps its git job. So `.graphifyignore` is a CURATED list of what to keep OUT OF THE GRAPH — NOT a blind copy of `.gitignore` (graphify already auto-skips deps/build/caches: `.venv`, `build`, `dist`, `node_modules`, `graphify-out`, `.git`, `__pycache__`).
    - **`.graphifyignore`** (COMMITTED at the repo root — NOT gitignored, so every machine picks it up): `generated/`, `.pack-tracker/`, `/tracker.toml`, `scripts/.bd119-pre-refactor-monolith.sh.snapshot`, `**/archive/`, `**/*-archive/` (covers `maintenance-docs/archive/` + `.../templates-archive/`), `scripts/tests/fixtures/` (synthetic test inputs), `test-fixtures/` (build-artifact tree). (`shared-docs/ios26/` is NOT included — no longer in the repo.)
    - **`.gitignore` edit:** ADD `graphify-out/`; REMOVE the defunct `shared-docs/ios26/` entry + its comment (the dir no longer exists). `.graphifyignore` is NOT added to `.gitignore`.
    - **Drift safeguard = NO CI check** (the earlier `⊇ .gitignore` superset-check idea was based on the wrong "replaces" model — dropped). Instead a **Pack Chat operating rule (proactive):** when something that looks like it should be graph-ignored appears (a new build/cache/archive/synthetic-data dir), Pack Chat ASKS the user whether to add it to `.graphifyignore`.
  **Scope:** the pack-root trinity `## Knowledge graph` rule (lock-step); the committed root `.graphifyignore`; the `.gitignore` edit (add `graphify-out/`, remove `shared-docs/ios26/`); the Option-B `graphify update .` pre-commit hook + the "docs changed" reminder hook (per-clone enable, documented); a `pack-ops/` Graphify how-to doc (build/update policy, the hybrid model, the proactive-ask rule); the initial `/graphify .` build (after `.graphifyignore` lands); the Pack Chat operating-rule additions (run the semantic update after doc-heavy commits; proactive `.graphifyignore` ask).
  **Out of scope:** any client (`project-template/`) Graphify wiring (clients don't necessarily have graphify); shipping graphify in the config pack; an ollama-backed hook (rejected — quality/speed); a CI graph-freshness gate (rejected — guards a local convenience + would force the token-costing semantic pass per commit).
  **Hard constraints:** boundary-absolute (pack-ops only; nothing in `project-template/`); the build's semantic pass uses the live session subscription (no API key); `graphify-out/` never committed; the hook is zero-token + non-staging + non-blocking.
  **Acceptance criteria (provisional — refined by design):** the pack-root trinity carries the graph-first rule (parity, audience-correct); a committed root `.graphifyignore` excludes exactly the curated set + graphify graphs the real source/docs (incl. `project-template/`) and excludes archives/fixtures/generated/local; `.gitignore` has `graphify-out/` (and no `shared-docs/ios26/`); the zero-token pre-commit hook + reminder documented; the pack-ops Graphify doc + the two operating rules landed; an initial graph built; `validate-pack` green; NO client-install/boundary regression.
