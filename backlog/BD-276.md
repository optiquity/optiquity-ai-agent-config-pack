**BD-276 — Systemic BSD-mktemp `-t` portability sweep (tests + runtime libs)**
Type: chore — pack-dev portability hardening (PACK-OPS + runtime scripts; NOT a client deliverable). The `mktemp [-d] -t <prefix>.XXXXXX` form is BSD-vs-GNU non-portable (BSD treats the `-t` argument as a PREFIX and appends its own random suffix, leaving a literal `XXXXXX` in the path); sweep to the portable full-template form.
Status: Open
Blockers: none (the affected sites currently PASS — they are not path-sensitive today).
Unblocks: cross-platform (macOS BSD + Linux GNU) parity for every mktemp site; removes a latent portability class that already surfaced once — it masked the BD-257 detection regression as a false "mktemp bug" (a real product regression was nearly written off as platform flakiness).
Position: pack-dev portability hardening; independent. Sequence AFTER the BD-257 detection fix + BD-274 (not blocking).
File/Symbol (coder enumerates the exact set at implementation):
  - ~50+ files / 200+ sites of `mktemp [-d] -t <prefix>.XXXXXX` across `scripts/tests/*.sh` + runtime libs (`scripts/lib/*.sh`, `immutable-manifest.sh`, `migrate-v10-to-v11.sh`, etc.).
  - Portable target form: `mktemp -d "${TMPDIR:-/tmp}/<prefix>.XXXXXX"` (full-path template — both BSD and GNU expand the `XXXXXX`).
Description: The BSD/GNU `mktemp -t` divergence leaves a literal `XXXXXX` in temp paths on macOS. Most sites are not path-sensitive (they pass), but the class is latent AND already caused a misdiagnosis: the BD-257 detection regression was first mistaken for a mktemp bug because `test-activate-capability.sh` uses this form. A VERIFIED sweep replaces every buggy `-t`-prefix site with the portable full-template form and confirms no test/behavior regresses. VERIFY each site is genuinely the `-t`-prefix form before rewriting (some `mktemp` calls are already portable — do not churn those).
  **Out of scope:** the order-dependent test flake (BD-275); the BD-257 detection regression (a BD-257 fix, not a mktemp issue).
