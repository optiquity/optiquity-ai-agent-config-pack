**BD-244 — CI guards enumerate git-tracked files, not the raw filesystem (strengthen `ci-guard-measure-then-bound`)**
Type: feat — Pack-memory rule strengthening. Adds a facet to the existing `ci-guard-measure-then-bound` rule (pack-root trinity ×3): a CI guard / validator / allowlist that enumerates repo files MUST derive its candidate set from git-TRACKED files (`git ls-files`), never a raw filesystem walk (`rglob` / `os.walk` / `find`), so untracked local artifacts (e.g. `.DS_Store`, editor temp files) can neither mask a true positive nor raise a false positive — with a graceful git-unavailable SKIP (per Check 63).

Description:
  Problem: a CI guard that walks the raw filesystem pulls untracked, gitignored, and OS-junk files into its candidate set. Such files are absent from CI's clean checkout and from fresh isolated worktrees but present in long-lived local dev checkouts — so a guard can pass everywhere it is normally exercised yet fail (or silently MASK a real hit) only on a developer's machine. BD-243's Check 69 hit exactly this failure mode.
  Goal: strengthen `ci-guard-measure-then-bound` with a tracked-files-only enumeration clause + the git-unavailable graceful-SKIP pattern, and census existing validate-pack checks for any remaining raw-fs-walk enumeration that should convert.
