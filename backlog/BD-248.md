**BD-248 — Persistent portable agent-handoff directory + pack-side write-fail fallback (reliability hardening, both surfaces)**
Type: feat — surfaced 2026-06-26 from the BD-206 handoff-path reliability discussion; user-approved open
Status: Resolved
Target: v11.0
Blockers: BD-206 — sequenced AFTER BD-206 finishes. BD-206 heavily edits the operating docs that this BD also touches (`pack-ops/PACK-CHAT.md`, `project-template/docs/pack/PM-CHAT.md`); landing this after avoids churning the same files concurrently. This is a SEQUENCING dependency, not a logical one.
Unblocks: durable agent IMPL/REPORT handoff that survives an OS `/tmp` eviction mid-cycle, and genuine pack/project symmetry on the handoff write-fail behavior.
File/Symbol:
  - **Pack-side handoff dir** — `pack-ops/PACK-CHAT.md` (the handoff-dir convention, currently the volatile `/tmp/pack-handoff-<bd>-<ts>/` example plus `<handoff>/IMPL-REPORT.md` and `<handoff>/changes.patch`). Replace the `/tmp` convention with a persistent, untracked location.
  - **Project-side handoff dir** — `project-template/docs/pack/PM-CHAT.md` (the handoff-dir convention, currently the volatile `/tmp/proj-handoff-<task>-<timestamp>/` example plus `<handoff>/REPORT.md`). Replace with the SAME persistent, untracked pattern. **PORTABILITY CONSTRAINT:** PM-CHAT.md ships to client installs, so the replacement MUST be machine-agnostic — NOT a user-specific path (`~/Developer/_tmp` is one machine only). Candidate shapes for the architect to weigh: a gitignored repo-local dir (e.g. under `.claude/`) vs a `$TMPDIR`/`$XDG_*`-derived path; the choice must be untracked AND persistent AND portable across client machines.
  - **Untracked coverage** — if the chosen location is repo-local, ensure the pack `.gitignore` and the client `.gitignore` template both cover it so handoff artifacts are never tracked on either surface.
  - **Pack-side write-fail fallback clause** — add to `pack-ops/PACK-CHAT.md` the write-fail fallback the project side already carries (PM-CHAT.md: the agent falls back to the prompt-named report path and reports the degradation rather than hard-erroring on a failed handoff write), closing the current asymmetry where only the project side documents graceful failure.
Description: The agent-handoff directory — where a spawned agent writes its IMPL-REPORT/REPORT and (post-review-clean) its patch — is named per-spawn under `/tmp` by the operating-doc convention on both surfaces (`pack-ops/PACK-CHAT.md`, `project-template/docs/pack/PM-CHAT.md`). `/tmp` is volatile: macOS can evict it at any time, so a report written mid-cycle can vanish. The coder's actual edits are NOT at risk — they live in the BD-226 worktree at `.claude/worktrees/agent-<id>` (gitignored), and the patch is regenerable via `git diff HEAD`; the exposed artifact is the IMPL/REPORT audit doc. This BD moves the handoff convention to a persistent, untracked, PORTABLE location on both surfaces and closes the pack/project asymmetry by adding the project-side write-fail fallback clause to the pack side. The handoff path is convention-only — an example in the two chat operating docs, NOT hardcoded in any script or agent definition — so the change is doc-localized; the portability constraint (PM-CHAT.md ships to clients) is what makes the location choice an architect decision rather than a one-line swap.
  **Out of scope:** the worktree mechanism itself (BD-197 / BD-226 — the actual edits already live there safely); changing WHICH artifacts are written, or the post-review-clean patch protocol; tracker work.
