Description:
  **Problem:** the rigorous large-BD development flow (BD-237 ran it end-to-end; BD-206 is running it) is not codified as an official standard — its adversarial-review + reconciliation stages exist only as out-of-repo memories (situational), and the full chain + the size-tiering are uncodified, so a fresh session/agent cannot rely on the standard.
  **Goal:** codify the PACK-SIDE flow as the DEFAULT STANDARD for LARGE BDs, with the two adversarial reviews + reconciliation OPTIONAL (user-elective) for SMALLER BDs.
  **The standard (full flow, with options):**
    1. **Optional researcher set — FIRST step, before the first architect.** Zero, one, or both of: an **INTERNAL** researcher (repo/codebase inventory + blast-radius census) and an **EXTERNAL** researcher (CLI / tool / framework / API docs verification against authoritative sources). "May be needed" — invoked per the BD; optional-by-need at ANY size.
    2. **Architect** → design, including the REQUIRED rule-10 parallel/dependency map.
    3. **Adversarial architect review** (fresh, clean-context instance) → Pack-Chat triage of findings → **[reconciliation architect — only if the review returns NEEDS-REWORK]**; loop until READY.
    4. **User design review** (the design gate).
    5. **Planner** → coder-ready plan, including its OWN rule-10 parallel/dependency map.
    6. **Adversarial planner review** (fresh instance) → triage → **[reconciliation planner — only if NEEDS-REWORK]**.
    7. **User planner-to-coder gate.**
    8. **Parallel worktree coder waves** — scheduled off the rule-10 map: disjoint-file commits run as concurrent coders, each in its own isolated worktree; same-file ⇒ serialize. Each commit's bounded review/fix cycle (≤2 review/fix pairs + 1 final) runs IN its worktree; the patch is produced only after review-clean; patches are applied to the canonical tree SEQUENTIALLY (atomic per patch) with the conflict protocol (STOP + re-spawn fresh, never hand-merge); commits land with user approval. Superseded design/plan docs are DELETED as the pipeline iterates (anti-contamination); the audit set is preserved into `maintenance-docs/v<major>-implementation/` (Constraint 3).
    The two adversarial passes are the MINIMUM for a large BD; ADDITIONAL architect/planner rounds are added when larger gaps are found.
  **Size-tiering (pack uses BDs):** **LARGE BD** = the full pipeline by default (the two adversarial reviews + reconciliation as the minimum). **SMALL BD** = the base flow (optional researcher → architect → planner → coder + the bounded review/fix cycle) with the two adversarial reviews + reconciliation OPTIONAL at user election. The architect defines the large-vs-small criterion measure-then-bound (e.g. launch-gate / cross-surface / blast-radius / structural — concrete, not a vibe).
  **Where it lives:** trinity `## Pack memory` is the SSOT, propagated per the "Keeping CLAUDE.md, AGENTS.md, GEMINI.md, and PACK-AGENTS.md current" rule-change procedure (corpus ×3 trinity + `[rationale:]` + `PACK-MEMORY-RATIONALE.md` bijection + `.spawn-rule-manifest.txt` + reference surfaces); + a consolidated lifecycle section in `pack-ops/PACK-CHAT.md` / `pack-ops/PACK-AGENTS.md` as the architect designs. The two existing OUT-OF-REPO adversarial memories are reconciled to point at the in-repo standard (trinity-wins).
  **Process:** architect-first per the pack-architect-spawn-protocol (touches rules + operating docs + trinity) → planner → coder; per the very standard it documents, this BD MAY itself warrant the adversarial passes if the architect deems it large.
Acceptance criteria: the pack-side large-BD pipeline is documented as ONE official, size-tiered standard (the full chain incl. the optional internal/external/both researcher first step + the large/small-BD criterion + adversarial-as-minimum-for-large / optional-for-small + reconciliation rounds + parallel-worktree coder waves keyed off the rule-10 map); it lives in the in-repo SSOT (trinity `## Pack memory` + the full propagation surfaces), NOT just out-of-repo memory; the two existing adversarial memories are reconciled to point at the in-repo standard (no contradiction, trinity-wins); no conflict with the existing researcher-first / spawn-protocol / planner-to-coder / worktree-isolation rules; `validate-pack` green (C3 rule↔rationale bijection, anti-restate, trinity parity, spawn-rule manifest); architect-designed (not Pack-Chat-authored).
