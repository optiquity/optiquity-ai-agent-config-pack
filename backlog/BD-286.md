**BD-286 — Guided pre-reconciliation: a shipped doc the client's AI agent follows to prepare conflict-prone files BEFORE migration so the trinity (dominant) pause class runs pause-free**

Status: Open
Target: v11.0 (CORE — the guide + the prepare→dry-run→apply flow, zero new migrator code). The batch-reconciliation-PLAN facet (below) is a user-authorized v11.1 follow-on (user 2026-08-12).
Blockers: None. Complementary to BD-283 (interactive migration — different persona/surface, no collision); disjoint from BD-285 (init-project.sh).
Unblocks: a client whose migrating AI agent (PM chat) can pre-reconcile the dominant (trinity) conflict class from a shipped guide, so the migration runs clean with no pause for those files.
File/Symbol (architect confirms at open-time): a NEW shipped guide under `supporting-docs/` (alongside `MIGRATION-v10-to-v11.md`; Check 93 no-leak applies); it references the migrator's own baseline source `git show v10:<pack-relpath>` (the 3-way BASE), the project→pack→class transform map (`scripts/migrate-v10-to-v11.sh` ~L96-122), the marker-preserve engine (`scripts/lib/marker-preserve.sh`) for trinity, and the truthful `--dry-run` (BD-281) as the verify backstop. No pack runtime/code change in the v11.0 core.
Description:
  **Problem:** on v10→v11 migration, files changed by BOTH the user AND the pack pause for reconciliation (BD-282 makes the pause calm; BD-283 makes it interactive at a TTY). The pack's PRIMARY user is an AI-agent-driven PM chat; for that persona a guide-the-agent-follows-to-pre-reconcile is a better fit than a TTY loop, and it can eliminate the pause entirely for the dominant conflict class.
  **What works (strategy exploration, 2026-08-12):** the migrator's text 3-way classifier (`scripts/lib/three-way.sh`) is BASE-RELATIVE — it compares BASE↔OURS and BASE↔THEIRS, never OURS↔THEIRS — so pre-EDITING a dual-changed GENERIC line doc can NEVER move it out of `real-merge-required` (it still pauses). BUT the **trinity** engine (`marker-preserve.sh`, BD-136) is CONTENT-AWARE: folding the client's customizations INTO the designated marker sections lets the out-of-marker body reconcile → clean graft → NO pause. Trinity (`CLAUDE/AGENTS/GEMINI.md`) is 3 of the 5 real conflicts observed in the BD-205 W3 real-content run (the dominant class); structured configs mostly auto-resolve already.
  **"Who added what" is deterministic** (not ambiguous): BASE = the pack's v10-tagged template (`git -C $PACK show v10:<pack-relpath>`, verified present); the client's additions = `diff BASE OURS` = exactly the migrator's own `.three-way.diff`, reproducible pre-migration. The guide gives this mechanical recipe (no reliance on client git-blame).
  **Goal (v11.0 core):** a shipped guide that lists the conflict-prone files + per-class prep instructions — trinity: get BASE (`git show v10:<file>`) + the v11 template, see your additions (`diff BASE OURS`), fold them into the marker sections; structured: conform; generic: (cannot be pre-fixed — use BD-283 interactive or the pause). Plus the safety flow: **prepare → `--dry-run` (confirm zero conflicts predicted) → `--apply`** (BD-281's truthful dry-run is the free verify backstop). Zero new migrator code.
  **Honest boundary:** generic line docs (`PM-CHAT.md`, `PACK-FEEDBACK.md` — 2 of the 5) CANNOT be made pause-free by pre-editing (base-relative classifier). They remain served by BD-283's interactive loop or the pause+`--resume`.
  **Deferred v11.1 facet (user-authorized 2026-08-12) — batch reconciliation-PLAN mode:** the ONLY way to make generic dual-changed docs pause-free WITH a merged result is a new migrator mode where the agent records a per-file decision (accept-pack / keep-yours / merged-content) that the migrator applies non-interactively (reusing BD-283's decision-apply core). LARGE; sequences after BD-283 (shares `apply.sh`). Tracked here as the v11.1 follow-on; open a v11.1 BD when that milestone begins.
Acceptance criteria (v11.0 core): the shipped guide enumerates every conflict-prone pack file + the per-class prep recipe (trinity marker-fold; structured; generic-not-pre-fixable) + the deterministic `git show v10:<file>` / `diff BASE OURS` who-added-what recipe + the prepare→dry-run-verify→apply flow; a prepared trinity file migrates with NO pause (demonstrated on a fixture); the guide is generic-worded (Check 93 no-leak, both legs); `validate-pack` green; no pack runtime/code change in the core (verify the diff is doc-only + any test).
