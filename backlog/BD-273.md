**BD-273 — Pack-side agent-scratch ownership isolation + deletion-boundary guard (pack dev-workflow safety)**
Type: chore — pack-dev-workflow hardening (PACK-OPS; NOT client-shipped). Prevent a spawned pack sub-agent from deleting files it does not own. Motivated by a 2026-07-26 incident: a fix-coder ran an unscoped `rm -rf ~/Developer/_tmp/bd257-*` on its own authority and swept up other agents' scratch (net-harmless — no committed content or handoff reports lost, verified). Root cause = a SHARED `_tmp` namespace + a broad cleanup glob, NOT `rm` itself; the existing `per-action-approval-sub-agents` rule was honor-system prose and was violated (twice this session). Project-side analog is BD-274 (separate surface, separate deliverable — mirrors the BD-224/BD-257 pack/project split).
Status: Resolved
Blockers: none. INTERIM MITIGATION LIVE: every spawn is assigned a unique owned work dir + a "write only there, delete only within it, never a broad glob" directive.
Position: pack-dev hardening; independent of the BD-257 waves (may land in parallel). Lands BEFORE BD-274.
Unblocks: durable prevention of cross-agent scratch deletion — an agent can no longer delete another agent's work or repo-bound-but-not-yet-tracked content.
File/Symbol (architect refines; the design surfaces):
  - The OWNERSHIP model: each spawned agent OWNS one unique `_tmp` dir (keyed to its unique spawn name); writes all output (report + scratch) there; deletes only WITHIN it; never touches another agent's dir, shared `_tmp` roots, the repo/worktree, or a glob broader than its own dir.
  - A Claude-only PreToolUse[Bash] deletion-BOUNDARY hook (pack `.claude/settings.json`): `agent_id`-gated (sub-agent only), PATH-SCOPED — denies a delete OUTSIDE the agent's owned dir while ALLOWING the agent's own `$WORK`/mktemp cleanup (MUST NOT break the `trap 'rm -rf "$WORK"' EXIT` `verification-harness` test pattern); fail-open, mirroring `scripts/hooks/modes-*.py`; installed via a `scripts/install-modes-hook.sh` extension. Ship the hook only if the feasibility probe confirms (a settings PreToolUse[Bash] hook fires for sub-agents + `agent_id` is reliably populated — the first architect pass found this FEASIBLE against current Claude Code docs).
  - Strengthen the `per-action-approval-sub-agents` rule (trinity `## Pack memory` + `PACK-MEMORY-RATIONALE.md`): agents delete nothing outside their owned dir; scratch is write-only; all cleanup is the orchestrator's/harness's job. Ship this rule strengthening UNCONDITIONALLY (regardless of the hook outcome).
Design provenance: a FRESH architect pass reframes the first deletion-guard architect strategy (2026-07-26, `maintenance-docs`-bound) from a verb-ban to this OWNERSHIP-ISOLATION model, reusing its feasibility findings + rule-strengthening draft.
