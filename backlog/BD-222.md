Type: feat — CI/test-infra anti-drift guard. A validate-pack check (measure-then-bound) that catches the bug CLASS that took BD-219's first sharded CI run red, so it cannot silently recur. Status: Resolved

Unblocks: a wired test that depends on the dev machine's environment (an authenticated `gh`, a `/Users/...` path, a masked-failure shell idiom) can no longer pass locally + slip into CI red — the guard FAILS loud at validate-pack time, before push.
Description:
  **Problem:** BD-219's first sharded CI run went red because three previously-DORMANT tests that C3 newly wired had latent environment dependencies that only surfaced off the dev machine: (a) a HARDCODED absolute dev path (`/Users/david/.../scripts/pack-td.sh`) that exists locally but not on the CI runner; (b) tracker-mode promote tests that call real `gh` (`gh label create`) WITHOUT a fake-`gh`-on-PATH shim, so they pass only because the dev machine's `gh` is authenticated and fail on CI's unauthenticated runner; (c) the `grep -c … || echo 0` "double-zero" antipattern that masks failures. Local pass was insufficient to catch any of these (root cause: the "confirm offline" check ran on the authenticated dev box). See `maintenance-docs/v11-implementation/ARCHITECTURE-BD-219-CI-FAILURE-DIAGNOSIS.md` + `…/PLAN-BD-219-CI-FIX.md` for the full incident.
  **Goal:** a STANDING, cheap validate-pack guard (measure-then-bound; `ci-check-runtime-compounding`-safe) that statically detects, in every WIRED test script, the recurrence of this bug class — so the failure is caught at validate-pack/PR time, not on a CI runner after push. The architect designs the exact detections + the allowlist for legitimate exceptions.
  **Scope (architect refines — candidate detections, NOT prescribed):**
    - Hardcoded absolute dev/home paths (`/Users/…`, `$HOME`-absolute) in wired test scripts.
    - A wired test that invokes real `gh` (live network/auth) WITHOUT either a fake-`gh` shim on PATH or an allowlist entry — i.e. an un-shimmed live-`gh` call in a CI-wired test.
    - The `… || echo 0` double-zero (and related failure-masking) idiom.
    - Measure the whole wired battery first; categorize each hit KEEP/STRIP; size the allowlist to exactly the legitimate set (the genuine live-gh manual-only tests already in `scripts/ci-test-wiring-allowlist.txt`).
  **Out of scope:** the BD-219 CI-fix itself (this guard generalizes it); changing the sharding; non-test source.
  **Hard constraints:** the guard is CHEAP (glob+regex over the wired test set; no subprocess-per-script; routed through `run_check` with a runtime budget); effectiveness-preserving; the design must include a CLEAN-ROOM verification recipe (the local-pass-is-insufficient lesson).
  **Acceptance criteria (provisional — refined by design):** a new validate-pack check FAILs on a wired test with a hardcoded dev path / un-shimmed live-`gh` / double-zero idiom and passes on the corrected tree; allowlist sized to the measured legitimate set; the check is cheap (per-check runtime budget held); full CI battery green.
