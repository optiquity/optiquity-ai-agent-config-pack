**BD-218 — Background-session isolation (`worktree.bgIsolation` + EnterWorktree/ExitWorktree); the background-job half of BD-197**
Type: feat — STRUCTURAL. The top-level **background-session** isolation axis that BD-197 deliberately scoped OUT. Split off on 2026-06-14 (user direction) after BD-197 probing established that subagent isolation (the Agent-tool `isolation:"worktree"` parameter + `worktree.baseRef`) and background-SESSION isolation (`worktree.bgIsolation` + the EnterWorktree/ExitWorktree flow) are TWO INDEPENDENT mechanisms — not the single matrix the BD-197 design first assumed. Spans pack-self + client surfaces. Full pipeline (researcher → architect → planner → coder, bounded review/fix).
Status: Deferred
Target: v11.1 (user 2026-06-14).
Blockers: BD-197 (the Claude-only subagent worktree-isolation model + the agent RW/RO classification + the agents-never-commit-preserving merge-back/IMPL-report mechanism + the OPTIONAL-FEATURES "isolated parallel agents" section must land first as the reference model + doc home).
Unblocks: a documented, verified "no destructive surprises" guarantee for users who run TOP-LEVEL BACKGROUND `claude` jobs (detached/headless sessions, incl. background Agent-Teams runs) — distinct from the foreground Pack/PM-Chat subagent path BD-197 ships.
Description:
  **Problem:** BD-197 makes worktree isolation work for the PRIMARY use case — a FOREGROUND Pack/PM Chat spawning SUBAGENTS via the Agent-tool `isolation:"worktree"` parameter (base controlled by `worktree.baseRef`: `head` = parent HEAD [required], default `fresh` = origin/<default>). BD-197 does NOT cover **background sessions**: top-level detached `claude` jobs governed by the SEPARATE `worktree.bgIsolation` setting. Per the Claude Code settings schema (verified 2026-06-14): `worktree.bgIsolation` ∈ `{"worktree","none"}`, default `"worktree"` — `"worktree"` BLOCKS Edit/Write in the main checkout until `EnterWorktree` is called; `"none"` lets background jobs edit the working copy directly. This is the "no destructive surprises for background jobs" safety gate, mediated by the `EnterWorktree`/`ExitWorktree` tools. It is untested + undocumented in the pack.
  **Why split from BD-197:** BD-197 probing (2026-06-13/14) proved the subagent path empirically (isolation param works fg+bg; `baseRef:"head"` bases at parent HEAD; orchestrator patch merge-back applies clean) and resolved the base axis from docs. The background-session axis requires launching a REAL top-level background session to verify — a human action that could not be performed inside the foreground probing session — and exercises a different mechanism (`bgIsolation` + EnterWorktree), so it is its own unit of work, not a BD-197 sub-step.
  **Scope (per the deferred BD-197 "(b)" probe + design):**
    - **Verify empirically** (verify-availability-not-just-existence): launch a real background `claude` session and test the `bgIsolation` gate under BOTH values — `"worktree"` (default → expect Edit/Write to main BLOCKED until `EnterWorktree`) and `"none"` (→ direct working-copy edits) — capturing runtime ground-truth, not trusting settings.
    - **Characterize the `EnterWorktree`/`ExitWorktree` flow**: what they create/base on (interaction with `baseRef`), how a background session merges work back preserving agents-never-commit, and TEAMS-on vs TEAMS-off behavior ("no destructive surprises" under all settings).
    - **Design pack guidance**: whether/how the pack documents + (optionally) recommends a `bgIsolation` posture; OPTIONAL-FEATURES coverage (additive to the BD-197 "isolated parallel agents" section, both surfaces, separately authored client-native); agent-instruction implications.
    - **Inherit BD-197's hard constraints**: agents-never-commit + the full destructive-git-verb ban RETAINED for ALL agents incl. RW; the pack ships/auto-writes NO settings file at any scope; "no destructive surprises."
  **Out of scope:** the subagent worktree-isolation model itself (BD-197); Codex/Gemini worktree/background analogs (BD-217); any change to BD-197's proven subagent path.
  **Acceptance criteria (provisional — refined by research):** background-session `bgIsolation` behavior verified under both `worktree`/`none` on the actual target version; the EnterWorktree/ExitWorktree merge-back path documented + preserving agents-never-commit; "no destructive surprises" guaranteed for background jobs under TEAMS-on and TEAMS-off; OPTIONAL-FEATURES + agent-instruction docs accurate + client-native; validate-pack green; no settings file shipped.
References: BD-197 (the subagent worktree-isolation reference model + merge-back/IMPL-report + OPTIONAL-FEATURES home; the two-independent-mechanisms finding); BD-217 (Codex/Gemini worktree analogs); the Claude Code settings schema `worktree.bgIsolation`/`baseRef` (verified 2026-06-14: https://www.schemastore.org/claude-code-settings.json) + EnterWorktree/ExitWorktree tools; the `verify-availability-not-just-existence` rule.
