Description:
  Under `isolation_mode: full` (all agents spawn `isolation:"worktree"`, read-only agents then `cd` to the target tree — `pack-ops/OPERATING-MODES.md` § Isolation mode), cross-tree git operation is broken in practice (user-observed; recorded in the session-state queue at BD-288 close — no failing command or error text was captured at the time). Under the default `read-write-only`, read-only agents spawn in-place and their traffic rides the inter-session mailbox channel: completion notifications are lost and platform bug #73647 prepends security boilerplate to every delivery (user-accepted 2026-07-21 as the lesser defect). Neither value is fully usable; `full` — the durable channel-hygiene lever — must work.
  Scope: (1) full investigation — reproduce the `full`-mode breakage under controlled conditions, capture the exact failing operations and errors verbatim, and root-cause it across the whole mechanism (spawn contract, `cd` semantics, the three enforcement hooks, worktree layout, graph/handoff path injection); (2) complete fix on BOTH surfaces, mirror-but-customize, including every encoding surface (contract docs, spawn preflights, trinity rules, hooks + their tests, per-CLI skill copies).
Acceptance criteria: root cause established with reproducible captured evidence, not inference; `full` mode verified working end-to-end by a live probe (a read-only agent spawns isolated, `cd`s to the target tree, runs read-only git verbs and writes its report — no failure, async-task channel preserved); pack and project analogs fixed in lock-step; every encoding surface updated (contract docs, hooks, per-CLI skill copies, tests); hook self-tests and the full CI battery green (both jobs + `PACK_VALIDATE_DEEP=1`).
