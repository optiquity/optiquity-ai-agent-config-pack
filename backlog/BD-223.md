**BD-223 — Ship a committed (public) test-fixtures suite + a separate private gitignored suite**
Type: feat — test-infra / release-readiness. Reorganize `test-fixtures/` so a COMMITTED (non-gitignored) fixture suite ships with the pack (the pack goes public soon — public users should be able to run the test suite WITHOUT first building fixtures), alongside a SEPARATE gitignored suite for the maintainer's own private use. Opened 2026-06-15 (user direction). Full pipeline (researcher-if-needed → architect → planner → coder → bounded review/fix).
Status: Open
Target: v11.0 TENTATIVE — could be deferred; **NOT a launch blocker** (user 2026-06-15). The pack ships + tests run today via `build.sh`; committed fixtures are a public-usability improvement, not a gate.
Blockers: BD-219 (the CI sharding + the dynamic-from-disk / location-based cohesion redesign land first; this reorganizes the same `test-fixtures/` tree + interacts with the fixture-build CI step). Sequence after BD-219 is Resolved.
Unblocks: a public/clone-able test run that does not require `test-fixtures/build.sh` first (committed fixtures present in the repo), while the maintainer keeps a private gitignored fixture set for local experimentation.
Description:
  **Problem:** `test-fixtures/` is currently a fully GITIGNORED build-artifact tree (deny-all `*` + a tiny un-ignore allowlist), generated by `test-fixtures/build.sh`. With the pack going public, a committed fixture suite would let users (and CI on a fresh clone) run the test battery without a build step. The user wants to split `test-fixtures/` into (1) a COMMITTED public suite and (2) a SEPARATE gitignored private suite.
  **Scope (architect refines — measure-then-bound the blast radius first):** the `test-fixtures/` directory reorganization (committed public suite + gitignored private suite + the `.gitignore` rule changes); the `test-fixtures/build.sh` build/verify orchestration; `test-fixtures/manifest.txt` + the `regenerate-manifest-v11-surface` rule; the per-shard fixture-build CI step (BD-219); install plumbing / `_CLIENT_INSTALLED_FILES`; the v10→v11 migrator; and every test that references a `test-fixtures/<name>` path. The BD-219 dynamic-autoregen architect's addendum (the location-based-cohesion assessment) already captured initial blast-radius evidence for this tree — reuse it.
  **Out of scope:** BD-219's CI sharding + the location-based test cohesion (`scripts/tests/fixture-dependent/`) — that ships in BD-219; this BD only reorganizes the FIXTURE DATA tree (committed vs private), not the test scripts.
  **Hard constraints:** the committed suite must be deterministic + reproducible by `build.sh` (no drift between committed fixtures and a fresh build); the private suite stays gitignored; manifest discipline preserved; no client-install regression.
  **Acceptance criteria (provisional — refined by design):** a committed public fixture suite present in the repo (CI on a fresh clone runs the battery without building); a separate gitignored private suite; `.gitignore` + `build.sh` + manifest + the fixture-build CI step reconciled; `validate-pack` green; no install-map/client regression.
References: BD-219 (the CI sharding + the dynamic-from-disk/location-cohesion redesign; the architect addendum `/tmp/handoff-bd219-redesign/ARCHITECTURE-BD-219-DYNAMIC-AUTOREGEN.md` blast-radius evidence — to be committed with BD-219); `test-fixtures/build.sh`; `test-fixtures/.gitignore`; the `regenerate-manifest-v11-surface` rule.
Resolved: n/a
