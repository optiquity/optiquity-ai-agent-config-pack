**BD-217 — Codex + Gemini worktree-isolation support (platform-specific; the cross-CLI half of BD-197)**
Type: feat — STRUCTURAL. The Codex-CLI and Gemini-CLI analogs of BD-197's Claude-only worktree-isolation + safe parallel-agent execution. Split out of BD-197 on 2026-06-13 (user direction) because each platform's worktree support differs materially and must be designed + implemented platform-specifically — not assumed parity. Spans pack-self + client surfaces. Full pipeline (researcher → architect → planner → coder → bounded review/fix), run per-platform.
Status: Deferred
Target: v11.1 (user 2026-06-13).
Blockers: BD-197 (the Claude-only worktree-isolation model + the agent read-write/read-only classification + the Pack-Chat-mediated merge-back/IMPL-report mechanism must land first as the reference model). Each platform then adapts that model to its own worktree feature set.
Unblocks: Codex-CLI and Gemini-CLI users get safe, opt-in worktree-isolated parallel agent execution equivalent (where the platform allows) to the Claude-only capability BD-197 ships — with platform-correct user-facing docs + agent-instruction docs.
Description:
  **Problem:** BD-197 establishes worktree isolation + the agents-never-commit-preserving merge-back model for Claude Code only. Codex CLI and Gemini CLI now have their OWN (immature, materially different) worktree support (P1 research RESEARCH-BD-197-P1-WORKTREE-ISOLATION.md: Gemini CLI experimental `--worktree`/`-w` through release 0.36.0; Codex worktree mode + subagent-in-worktree pattern — both with open subagent-cwd / data-safety bugs). A blanket "trinity-exempt, Claude-only" stance leaves these platforms either unsupported or unsafe; parity cannot be assumed.
  **Scope (per-platform, NOT a byte-copy of the Claude design):**
    - Per-platform research of the actual worktree feature set, flags/config, subagent-in-worktree behavior, and data-safety bugs (verify-availability-not-just-existence: GA vs experimental, version-sensitivity).
    - Adapt BD-197's agent read-write/read-only classification + the agents-never-commit-preserving merge-back/IMPL-report mechanism to each platform's mechanics.
    - Platform-correct USER-FACING docs (the OPTIONAL-FEATURES walkthrough per CLI) AND AGENT-INSTRUCTION docs (the AGENTS.md / GEMINI.md trinity analogs + per-CLI agent files) — each authored to that platform's reality, per the cross-CLI-reference-normalization rule (audience-correct, not byte-identical to the Claude text).
    - Graceful degradation: where a platform's worktree support is absent/unsafe, that CLI degrades to non-isolated sequential agents with zero failures (same guarantee as BD-197).
  **Hard constraints (inherited from BD-197):** agents-never-commit + the full destructive-git-verb ban is RETAINED on every platform; no settings file shipped/auto-written; "no destructive surprises" — defensive against each platform's worktree data-loss bugs.
  **Out of scope:** the Claude-only model itself (BD-197); any platform whose worktree support is too immature/unsafe to support responsibly (declare unsupported + degrade, per-platform decision at design time).
  **Pipeline:** researcher → architect → planner → coder, run per-platform (Codex and Gemini may be separate sub-efforts given how different they are); bounded review/fix per commit.
  **Acceptance criteria (provisional — refined by research):** each supported platform has opt-in worktree-isolated parallel execution matching its native worktree feature set; agents-never-commit + verb-ban preserved; user-facing + agent-instruction docs platform-correct; graceful degradation verified; validate-pack green; no settings file shipped.
References: BD-197 (the Claude-only reference model + the merge-back/IMPL-report mechanism + the agent RW/RO classification); RESEARCH-BD-197-P1-WORKTREE-ISOLATION.md (the cross-CLI findings: Gemini/Codex worktree support + bugs); the cross-CLI-reference-normalization rule (ARCHITECTURE-BD-182 §4.1); the trinity exemption pattern.
