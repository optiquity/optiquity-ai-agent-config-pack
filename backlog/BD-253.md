Blockers: BD-252 — sequenced AFTER BD-252 (the pack side designs the resumable-snapshot pattern first; the project side adapts it). This is NOT a copy: the project side already ships state mechanisms (`docs/project/implementation-plan/_index.md`, `STATUS.md`, and other project state) that this BD must RECONCILE with, not duplicate.
Unblocks: a client PM-Chat session that is fully transferable + restartable — survives /pm-startup, machine transfer, and CLI transfer (Claude ↔ Codex ↔ Antigravity) — with nothing necessary-to-resume lost.
Problem: the project-side (client) PM-Chat has the SAME live-state resilience gap as Pack Chat (BD-252) — live orchestration state that does not transfer — BUT the project side ALREADY ships partial state mechanisms (the impl-plan `_index.md`, `STATUS.md`, etc.). Those were not designed for full cross-machine/cross-CLI resumability and may lean on CLI memory or volatile context for the live-orchestration layer. This BD brings the project side to the same bar as BD-252 by RECONCILING/EXTENDING the existing mechanisms — not by bolting on a parallel duplicate.
Requirements (SAME firm rules as BD-252, applied to the client surface):
  - Repo-committed (the client's repo); CLI-agnostic / trinity-agnostic; CLI memory FORBIDDEN for state on every CLI.
  - Transferable + restartable across machine + CLI; `/pm-startup` reads + sets the resume state.
  - Pause/resume = RE-SPAWN from the snapshot; last commit = durable boundary.
  - Parallelization mode + queue order captured; current-snapshot-ONLY, never history (history stays in the existing project mechanisms, isolated).
  - Consistency / no-stale enforcement via the shipped client doc-gate (`project-template/scripts/validate-docs.sh`) + `validate-pack` parity checks; nothing may go stale.
Architect-to-decide (design charges):
  - **Reconciliation:** what `_index.md` (impl-plan topological order + membership), `STATUS.md` (the convenience view, already "never source of truth"), and any other existing project state ALREADY cover, vs the live-orchestration gap this BD fills; whether the resumable snapshot is a NEW artifact or an EXTENSION of an existing one — avoid a duplicate/competing SSOT.
  - **State boundary:** what must persist to resume vs what is recreatable (mirrors BD-252's Q2 charge for the client surface).
