# .operating-doc-history-allowlist.txt — Check-65 KEEP allowlist (BD-243)
#
# The operating-doc no-history gate (Check 65, scripts/validate-pack.py
# check_operating_doc_no_history) scans the operating-doc IN set for
# history / audit-trail patterns (dates / 7-40-hex SHAs / Commit-N /
# Override-N / post-Commit / BD past-action / per-BD provenance / pre-date
# / User-locked / incident / carry-over / bare BD-NNN tag). These belong in
# IMPL reports + reference docs, NOT in a forward-only operating doc.
#
# THE TEETH: history-pattern count = 0 OUTSIDE this allowlist. A hit on any
# line NOT listed here FAILS the gate. ANCHOR-EXEMPT FIRST (an allowlisted
# snippet on the line clears it) THEN residue FAILs. This allowlist is sized
# to the KEEP set EXACTLY (measure-then-bound, ARCHITECTURE §6 SC1 +
# CLAUDE.md "CI guard design — measure-then-bound"): every entry is a live
# doc-ref, a live transitional pointer, or a format/grammar example — NOT a
# contamination hit widened in to make the gate pass.
#
# KEEP basis — two tests gate every entry: (T-live) the token points at LIVE
# PENDING work the agent must act on, AND (T-def) keeping it does NOT require
# describing a deferred/unimplemented feature. A KEEP passes T-live AND fails
# T-def (a live pointer that is not itself a deferred-feature description).
# A reviewer re-verifies each `reason:` still names LIVE-and-CURRENT work.
#
# K-set (BD-243 DESIGN §B.1): K1 live transitional pointer; K2-K6 live doc
# cross-refs; K7 filename/grammar examples; K9-K11 date format examples;
# K12 the new no-history rule's own self-defining lines (the rule quotes the
# forbidden shapes verbatim — the rule defining itself, not provenance);
# K13 live maintenance-doc cross-refs whose filename embeds a BD number (the
# BD digits are in the path, not provenance — the doc exists + is read at
# task time, the same class as K2-K6 but the BD is carried by the filename).
#
# FORMAT: one allowlisted occurrence per record, blank-line separated.
#   doc:      <path relative to repo root>
#   pattern:  the forbidden-pattern class this occurrence matches
#   snippet:  a stable substring of the allowlisted line (content-anchored,
#             so a line that MOVES is still matched and a line whose content
#             CHANGES stops matching — line numbers are NOT the key)
#   reason:   why this occurrence is legitimate (live pointer / doc-ref /
#             format example), not provenance
#
# The check matches an occurrence to a record when the doc matches AND the
# record's `snippet` is a substring of the offending line.
