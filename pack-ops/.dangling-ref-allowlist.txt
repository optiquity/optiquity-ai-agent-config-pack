# .dangling-ref-allowlist.txt — Check-68 KEEP allowlist (BD-243)
#
# The dangling-reference gate (Check 68, scripts/validate-pack.py
# check_dangling_file_refs) is BD-243 Gate 3: it extracts file/path references
# (backtick bare-ref `FILE.ext`, markdown hyperlink, and the NEW qualified-path
# backtick `dir/.../FILE.ext`) from the operating-doc IN set + the Check-64
# deliverable surface (README layout + project-template/** + supporting-docs/**)
# and FAILs on any reference whose target does not exist — a dead pointer. It
# generalizes Check 64's existence-gate pattern, reusing Check 40's extraction
# (`_strip_code_blocks`, the bare-ref/hyperlink regex, the `_CHECK_40_ANCHOR_
# PHRASES` self-flagging-non-existence window, and the basename index).
#
# THE TEETH: a reference that resolves to NO file (qualified-path direct +
# basename-index fallback) AND is NOT cleared by the anchor-phrase window AND
# is NOT on this allowlist FAILs. measure-then-bound (CLAUDE.md "CI guard
# design — measure-then-bound"): this allowlist is sized EXACTLY to the
# measured intentional-non-existence KEEP set — filename/path grammar patterns,
# regenerated-mirror references, runtime-generated outputs, template
# placeholders, out-of-repo memory files, and teaching/example client paths.
# Every token here is a reference that is dangling BY DESIGN. A new dangling
# ref must be EITHER fixed (restore/correct the target) OR, if it is
# intentionally non-existent, added here WITH a reason; it is NEVER auto-
# allowlisted. Any unclassified dangling ref is a BLOCKER.
#
# Record format (parsed by _parse_manifest_records; ONE blank line BETWEEN
# records; matched by exact token):
#   token:  the exact dangling reference as cited (a bare basename like
#           `BD-NNN.md` OR a qualified path like `docs/project/STATUS.md`).
#           A reference whose extracted token == this value is cleared.
#   reason: why this reference is dangling by design (KEEP).
