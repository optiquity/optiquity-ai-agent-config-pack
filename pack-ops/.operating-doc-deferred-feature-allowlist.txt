# .operating-doc-deferred-feature-allowlist.txt — Check-67 KEEP allowlist (BD-243)
#
# The operating-doc deferred-feature RECALL gate (Check 67, scripts/validate-
# pack.py check_operating_doc_no_deferred_feature) is BD-243 Gate 2: it scans
# the operating-doc IN set (_iter_operating_docs) for lines that ADVERTISE a
# deferred / unimplemented / future-version FEATURE (markers: deferred /
# future version / coming soon / not-yet-created / once X lands|ships /
# roadmap / planned post / will ship / v11.1|v11.x / slated / expected to
# offer). It is a RECALL gate, NOT precision: it flags every marker-bearing
# line, and this allowlist clears the genuine operative KEEPs; anything else
# FAILS.
#
# THE TEETH: marker-pattern count = 0 OUTSIDE this allowlist. A hit on any
# line NOT cleared by a (doc, snippet-substring) record FAILS. The allowlist is
# sized to the KEEP set EXACTLY (measure-then-bound, CLAUDE.md "CI guard design
# — measure-then-bound"): every record is one of the four measured KEEP
# categories below — NOT a contamination hit widened in to make the gate pass.
# A new marker hit must be EITHER stripped (it advertises a deferred pack
# feature) OR, if it is a live workflow / generic advice / the rule itself,
# added here WITH a reason a reviewer re-verifies. It is NEVER auto-allowlisted;
# any unclassified hit is a BLOCKER.
#
# NOTE (D-1, BD-243): the CB-08 strip already cleaned PLATFORM-SKILLS.md's
# deferred-skills catalog to current-state-only, so there is NO catalog block
# here — PLATFORM-SKILLS contributes ZERO records. Any future PLATFORM-SKILLS
# marker hit is therefore a regression, caught loudly.
#
# THE FOUR MEASURED KEEP CATEGORIES (DESIGN-BD-243-DURABLE-GATES.md §3 Gate 2):
#   C1 — the deferral/operating-doc RULES describing what they forbid + the
#        deferral-discipline rules (trinity + RATIONALE). The rule naming
#        "deferred-feature mentions" / "No deferral to v11.1+" is the rule
#        describing its own scope, not a deferred-feature advertisement.
#   C2 — generic client-PRODUCT advice (the client's own API/feature evolution,
#        not a pack feature): api-design "remove in a future version";
#        ios/swift platform-pattern deferral.
#   C3 — operative current-state caveats (a generic extension caveat, not a
#        specific feature promise): OPTIONAL-FEATURES "added here once they
#        ship and prove useful".
#   C4 — the LIVE TD-deferral WORKFLOW feature (the coder "Deferred items"
#        report section, the BLOCKED-triage "not-yet-landed artifact" rubric,
#        the deferral-discipline rules, the BACKLOG `Deferred` status). These
#        document a LIVE workflow, not a deferred pack feature.
#
# Record format (parsed by _parse_manifest_records; matched (doc, snippet)):
#   doc:     repo-relative path of the operating doc
#   snippet: a stable substring of the KEEP line (content-anchored; survives
#            a line move; if the content changes the snippet stops matching and
#            the gate re-fires, forcing re-adjudication)
#   reason:  the KEEP category + why this is not a deferred-pack-feature mention
