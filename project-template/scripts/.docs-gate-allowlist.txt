# .docs-gate-allowlist.txt — KEEP allowlist for the operating-doc gate
# (scripts/validate-docs.sh).
#
# The gate scans the project operating docs on four axes (history /
# deferred / bloat / dangling). A hit on any line that is NOT covered here
# FAILS the gate. This allowlist is sized EXACTLY to the legitimate KEEP
# set — every record is a rule self-reference, a live TD-deferral workflow
# line, generic product advice, a format example, an irreducible
# enumeration, or a will-exist-at-install file cross-reference. It is NOT
# widened to admit a borderline hit: if a new hit is not clearly one of
# those, fix the doc instead of adding a record.
#
# History stores (the per-entry streams under
# docs/project/{backlog,implementation-plan,changelog}/, docs/reference/,
# completion reports) are EXCLUDED from the operating-doc scan entirely —
# they legitimately carry dates and deferral narrative, so they are never
# line-allowlisted here. (Under the no-mirror flat-file model there is no
# regenerated monolith mirror to exclude.)
#
# FORMAT: one record per blank-line-separated block; '#'-comment lines
# ignored. Two record shapes:
#
#   Snippet record (history / deferred / bloat axes):
#     doc:      <path relative to the project root>
#     pattern:  the axis / pattern class the hit belongs to
#     snippet:  a stable substring of the allowlisted line (content-anchored
#               — a line that moves is still matched; a line whose content
#               changes stops matching, so the gate re-bites a reworded hit)
#     reason:   why this occurrence is legitimate
#
#   Target record (dangling axis):
#     target:   <path that resolves only after install / project use>
#     reason:   why a reference to that target is legitimate
#
# The developer may add x-<concept> records the same way for project-custom
# skills / agents. Re-verify each reason: still names live-and-current work
# when an operating doc is reworked.
