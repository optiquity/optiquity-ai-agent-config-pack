### POQ-2 — live `/backlog/` parses 209/212 via the strict header regex — **MUST (hard-gate at C-7); correctly C-5-out-of-scope as a fix, but NOT merely cosmetic**
- **Evidence (re-measured at HEAD `f36ab99`):** `tmf_parse_backlog_tree "pack-backlog"
  "$PWD/backlog"` against the REAL tree → **209 entries** parsed, while the tree holds **212**
  matching files. The 3 dropped entries are:
  - `BD-167b` — header `**BD-167b — ...**` (suffix `b`; the parse regex `^\*\*((?:BD|TD)-\d{3})`
    requires exactly 3 digits, no suffix)
  - `BD-169b` — same suffix failure
  - `BD-195` — header `**BD-195 (Code Red 3) — ...**` (a parenthetical between the ID and the
    `—`; the regex expects `\s*[—-]` immediately after the ID)
- **This is exactly the architecture's own stress set.** ARCHITECTURE-BD-204.md §3 names "a suffix
  entry, a parenthetical entry, a Deferred entry, and a large multi-block entry" as the four
  lossless-oracle stress cases. POQ-2 is the live manifestation of two of those four. A forward
  migration that silently drops `BD-167b`/`BD-169b`/`BD-195` is a **lossless-round-trip FAILURE**
  on 3 of the pack's own 212 entries — the precise failure class BD-204's acceptance criteria
  ("every BD → an issue, EVERY entry preserved") forbid.
- **Correctly C-5-out-of-scope as a FIX?** As a code change, YES — C-5's named scope is the
  read-input repoint + Step-10 retire, and the integration tests use BD-NNN 3-digit fixtures only,
  so C-5 is internally consistent and green. The suffix/parenthetical parse-grammar fix is a
  distinct concern (it lives in `_tmf_parse_backlog_file`'s `ENTRY_HEADER` regex, shared with the
  client). The coder correctly surfaced it rather than expanding scope.
- **But it is NOT correctly gated by C-7 yet — and that is the risk.** The plan ASSERTS C-7's
  oracle carries suffix + parenthetical stress entries and is DYNAMIC/count-based, which WOULD
  catch this. However, the C-7 oracle fixture is hand-authored; if it uses 3-digit-only IDs (as
  the current C-5 fixtures do), it will pass green while the live tree still drops 3 entries. The
  **count oracle must run against the REAL pack tree (or a fixture that replicates the exact
  `BD-167b`/`BD-195` header shapes), and must measure 212==212, not a synthetic subset.**
- **Severity: MUST (at C-7/C-8 gate; not a C-5 commit blocker).** C-5 may land as-is (green,
  in-scope). But this finding MUST be carried forward as a HARD gate condition on C-7: the lossless
  oracle's count + identity legs must include the suffix + parenthetical header shapes and assert
  zero drops against the live 212. If C-7 lands with 3-digit-only fixtures, the C-8 flip will
  silently lose `BD-167b`, `BD-169b`, `BD-195`. Recommend recording this as an explicit C-7
  acceptance line in BD-204 (alongside the existing `Deferred`-stress hard-gate at line 23).
