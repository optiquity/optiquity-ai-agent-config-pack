## 0. HEADLINE (read this first)

1. **The single most decision-relevant fact: Gemini CLI is being DEPRECATED on 2026-06-18 (3 days from this research) and replaced by the Antigravity CLI.** Google's official Developers Blog ("An important update: Transitioning Gemini CLI to Antigravity CLI", retrieved 2026-06-15) states Gemini CLI + Gemini Code Assist IDE extensions **stop serving consumer requests on 2026-06-18** for AI Pro/Ultra and free individuals; only org Code-Assist Standard/Enterprise licensees keep legacy access. **This moots almost all standalone Gemini-CLI worktree investment** and confirms the BD-217-expansion + BD-221 direction: the forward Google platform is Antigravity, not Gemini.

2. **Antigravity is NOT pre-GA-and-uninspectable any more — the BD-201 "GA ~2026-06-18" estimate is now stale.** Antigravity launched as a free public preview in **Nov 2025**, and **Antigravity 2.0 shipped at Google I/O on 2026-05-19** as a five-surface platform (desktop IDE, **CLI**, SDK, Managed Agents API, Enterprise platform). The **Antigravity CLI is publicly available to everyone today** and is publicly documented at `antigravity.google/docs`. It is still labeled **public preview / free-for-individuals** (not "GA" in the strict commercial sense), but it IS publicly inspectable RIGHT NOW — so BD-217/BD-221 research need not wait for a future GA date. (The "~06-18" date in BD-201 is actually the Gemini-CLI DEPRECATION date, not an Antigravity GA date — those two were conflated.)

3. **Antigravity has the STRONGEST native worktree+subagent story of the three** — and it is the most BD-197-aligned. Per official docs (`antigravity.google/docs/subagents`, `/docs/cli-features`, retrieved 2026-06-15): subagents can **autonomously create an isolated Git worktree**, the parent **retains full access to the subagent's worktree**, **cleanup is automatic**, subagents **post their diff back into the conversation when finished**, and a **"Request Review" setting forces the agent to pause and show diffs before applying** + a **Planning Mode** that produces a diff proposal **without writing to disk**. That review-before-apply + diff-handoff posture is a near-native fit for BD-197's "agents-never-commit, parent merges" model. BUT it carries open worktree data-safety bugs (see §3 + the matrix) — EXISTS-AND-PROMISING, not yet PROVEN-SAFE.

4. **Codex CLI: subagent worktree isolation works as a PATTERN, but the key primitive BD-197 needs is still an OPEN feature request.** `spawn_agent` **cannot yet target a specified worktree directory** (issue #23095, OPEN, filed 2026-05-17), and the **native CLI `--worktree` flag is still an open/unmerged feature request** (issue #12862, OPEN since 2026-02-26). Codex worktree isolation today is "manage worktrees yourself + an architectural subagent pattern," not a first-class CLI flag. Multiple **cwd-confusion / changes-leak-to-main-checkout bugs are open** (#21432, #12232, #16525). EXISTS-AS-PATTERN-BUT-IMMATURE.

5. **The SAME data-safety failure mode BD-197 worried about is open on ALL THREE platforms in 2026**: "worktree changes silently land in the PARENT working tree instead of the isolated worktree" (Codex #21432/#12232/#16525; Antigravity forum reports 142303 / "worktree option does not work correctly"; Gemini #16940 / #22658). Plus a shared cross-tool hazard: stale `extensions.worktreeConfig=true` left in `.git/config` by one tool breaks the others (Claude-Code #45645; Antigravity forum 137246/142574/137358). Any BD-217 design must defend against this on every platform regardless of how mature each one's worktree feature looks on paper.

6. **Net version recommendation (detail + citations in §1–§3):**
   - **Codex CLI → v11.1, feasible-with-caveats.** Forward platform; pattern exists; design BD-197-style `/tmp`-patch handoff that does NOT depend on the unmerged `--worktree` flag or on the open `spawn_agent` workdir param. Re-verify #23095/#12862 at design time — if either lands, the design simplifies.
   - **Antigravity → defer to the SAME v11.x minor as BD-221 (NOT v11.0; likely v11.1/v11.2), feasible-and-well-fit.** Antigravity is publicly inspectable now, so research can proceed; but the worktree+subagent surface MUST be the surface BD-221 establishes (config dir, agent model, MCP config) — do the worktree work AS PART OF / immediately AFTER BD-221, not against the departing Gemini.
   - **Gemini CLI → do NOT invest. Declare unsupported + graceful-degrade; fold any residual into BD-221.** It is deprecated in 3 days; standalone Gemini worktree work would be obsolete on arrival.

## 2. PER-PLATFORM SUPPORTABILITY + VERSION RECOMMENDATION (researcher's own conclusion)

### 2.1 Codex CLI → **v11.1, FEASIBLE (with caveats)**
- **Recommendation:** Support in **v11.1**. Codex is a first-class forward platform; the user-facing + agent-instruction docs and a graceful-degradation design are worth building.
- **Design constraint (from the evidence):** Do **not** predicate the design on the native `--worktree` flag (#12862 OPEN) or on `spawn_agent` taking a worktree dir (#23095 OPEN). Build the BD-197-shape mechanism on what EXISTS today: a subagent runs in a user/orchestrator-created worktree (or in-place), runs `git diff` (read-only), and hands the patch off (e.g., to a `/tmp` handoff dir) for the orchestrator to apply — preserving agents-never-commit. The documented Codex "create worktree → `codex exec` workspace-write → present diff before applying" pattern is the proof this is achievable.
- **Caveat / re-verify-at-design:** the cwd-leak bugs (#21432, #12232, #16525) mean the design must NOT trust that a subagent's edits stayed in the worktree — verify the actual write location (ground-truth pwd/HEAD) at runtime, exactly as BD-197's Claude design does. If #23095 or #12862 lands before the architect runs, re-scope to use the first-class primitive (simpler, safer).
- **Degradation:** where the orchestrated-worktree pattern is unavailable/unsafe, degrade to in-place sequential subagents with zero failures (the BD-197 guarantee).

### 2.2 Antigravity CLI → **gate on / co-sequence with BD-221; NOT v11.0; likely v11.1–v11.2; FEASIBLE and BEST-FIT**
- **Recommendation:** Antigravity worktree isolation is the **most valuable and best-fitting** of the three, BUT it must NOT be designed in isolation from **BD-221** (the Gemini→Antigravity transition). The Antigravity config dir, agent/subagent model, and MCP config (`~/.gemini/antigravity-cli/`, `mcp_config.json`) are the SAME surfaces BD-221 establishes. Doing worktree work first would build on a config/agent surface BD-221 hasn't landed yet. **Sequence BD-217-Antigravity AS PART OF or IMMEDIATELY AFTER BD-221**, in the same v11.x minor BD-221 targets.
- **Why feasible/best-fit:** native subagent worktree creation + auto-cleanup + parent-retains-access + diff-posted-back + "Request Review" + Planning-Mode-no-disk-write together give an almost out-of-the-box agents-never-commit-preserving merge-back. The pack's job is mostly docs + a thin orchestration convention, not a from-scratch mechanism.
- **Caveat / re-verify-at-design:** preview-labeled + open worktree-leak bugs (forum 142303) + the stale-`worktreeConfig` cross-tool breakage (forum 137358/142574) + Google has been trimming free-tier limits. Treat as EXISTS-BUT-PREVIEW per `verify-availability-not-just-existence`: design only against documented, currently-available behavior; re-verify the worktree bug status + the exact config-dir/agent-file layout at design time (the layout is still settling — community sources show both `~/.gemini/antigravity-cli/` and `~/.config/antigravity/config.toml`; confirm against official docs before the architect commits paths).

### 2.3 Gemini CLI → **DO NOT INVEST; declare unsupported + graceful-degrade; fold into BD-221**
- **Recommendation:** Do **not** build standalone Gemini-CLI worktree isolation. It is **deprecated 2026-06-18** (3 days out). Any worktree mechanism + docs authored against Gemini would be obsolete on arrival and would have to be re-authored for Antigravity immediately.
- **What to do instead:** BD-217 should explicitly DECLARE Gemini CLI an unsupported-for-worktree-isolation platform and **degrade to non-isolated sequential agents with zero failures** (the BD-197 guarantee) for whatever residual Gemini support exists until BD-221 removes it. Hand the "Gemini worktree" line item to **BD-221** as part of the wholesale Gemini→Antigravity conversion — there is no separate Gemini worktree deliverable.
- **Note:** the legacy `--worktree`/`-w` (experimental, v0.36.0+) does technically exist and is usable until the deprecation, but `verify-availability-not-just-existence` cuts against investing in a capability whose host platform is being shut off — "exists" here is dominated by "about to be removed."

## 4. PER-PLATFORM DETAIL + CITATIONS

### 4.1 Codex CLI
- **Native worktree flag = OPEN feature request.** Issue #12862 "CLI: add `--worktree` and `--tmux` flags for one-command isolated sessions" (openai/codex, opened 2026-02-26, **OPEN/unmerged** as of 2026-06-15); #13356 closed as duplicate of it. CLI users manage worktrees manually with standard git today.
- **Subagent → worktree dir = OPEN gap (the BD-197-critical primitive).** Issue #23095 "Allow `spawn_agent` to start subagents in a specified workspace/worktree directory" (opened 2026-05-17 by michaeltyson, label enhancement, **OPEN**). Exactly the coordinator-creates-worktree-then-spawns-worker-into-it pattern BD-197 uses — currently unsupported natively.
- **Subagent config + inheritance (works).** Custom agents via TOML under `~/.codex/agents/` (personal) or `.codex/agents/` (project); subagents inherit sandbox/network rules + `.codex/config.toml` profile layering, stable since **v0.115.0 (2026-03-16)** (developers.openai.com/codex changelog + subagents docs). No peer-messaging (carried from P1: #12462).
- **Data-safety bugs (OPEN):** #21432 "Fork into new worktree leaves terminal cwd in original checkout" → edits meant for the worktree hit the main/local checkout; #12232 "Codex confuses cwd with target worktree" (model regresses to original cwd as context fills); #16525 (Windows) malformed cwd combining worktree + main checkout paths → apply_patch can hit the wrong checkout.
- **Merge-back feasibility:** the documented Codex worktree pattern (`developers.openai.com/codex` + community: "create worktree → `codex exec` workspace-write → present diff for review before applying") proves a `git diff` → `/tmp` handoff → orchestrator-applies design is achievable WITHOUT the open primitives, preserving agents-never-commit.
- **Sources:** github.com/openai/codex/issues/12862, /23095, /21432, /12232, /16525; developers.openai.com/codex/changelog; developers.openai.com/codex/subagents; codex.danielvaughan.com worktree/subagent posts (community, corroborating). All retrieved 2026-06-15.

### 4.2 Antigravity CLI (forward Google platform)
- **Availability:** original Antigravity = free public preview Nov 2025; **Antigravity 2.0 + CLI at Google I/O 2026-05-19** ("Antigravity CLI is available to everyone today"); five surfaces (IDE/CLI/SDK/Managed Agents API/Enterprise). Public docs at `antigravity.google/docs`. Label = public preview, free for individuals; enterprise via Gemini Enterprise Agent Platform. (developers.googleblog.com Antigravity announce + transition posts; antigravity.google/blog/introducing-google-antigravity-2-0.)
- **Native worktree + subagent (works, preview):** "New Worktree" on conversation start provisions a worktree in the background; **subagents autonomously create isolated worktrees when work needs isolation and auto-clean them up**; **parent retains full access to the subagent's worktree**; subagents **post their diff back to the conversation when finished** (antigravity.google/docs/subagents, /docs/cli-features, /blog/google-io-2026-feature-deep-dive).
- **Review-before-apply (the agents-never-commit fit):** **Planning Mode** proposes changes as a **diff preview without writing to disk**; default lets an agent accept its own changes, but **"Request Review" forces pause-and-show-diff before applying** (antigravitylab.net agents/auto-accept guides + agentpedia.codes security guide, corroborating community sources; align with official `/docs/agent-permissions`, `/docs/cli-permissions`).
- **Permissions model:** subagents inherit the parent's allowed command prefixes + file read/write directory scopes; "the main agent decides what tools/permissions subagents get, including whether they can write files" (antigravity.google/docs/subagents, /docs/agent-permissions). This is a clean lever for an agents-never-commit posture (deny write/commit at the subagent boundary; orchestrator applies the diff).
- **Config layout (STILL SETTLING — re-verify at design):** community sources report `~/.gemini/antigravity-cli/` (settings.json, mcp_config.json, plugins/, keybindings.json) AND `~/.config/antigravity/config.toml`; global AGENTS.md at `~/.gemini/AGENTS.md`, project AGENTS.md at repo root; workspace MCP at `.agents/mcp_config.json`. The `mcp_config.json` path matches BD-201's anticipated relocation. CONFIRM exact paths against official docs before the architect commits them.
- **Data-safety bugs (OPEN):** Google AI Dev Forum 142303 "Worktree option does not work correctly — changes for current task still go to current parent workspace"; lbjlaq/Antigravity-Manager #3067 (same symptom); agent silently dies on repos with `extensions.worktreeConfig=true` + `repositoryformatversion=0` left by other tools (forum 137358/142574/137246). Same leak-to-parent class BD-197 worried about + a cross-tool config hazard.
- **Sources:** developers.googleblog.com (Antigravity announce + "transitioning Gemini CLI to Antigravity CLI"); antigravity.google/docs/{subagents,cli-features,cli-overview,agent-permissions,cli-permissions}; discuss.ai.google.dev threads 142303/137358/142574/137246; community (antigravitylab.net, datacamp, dev.to, medium google-cloud). All retrieved 2026-06-15.

### 4.3 Gemini CLI (legacy / deprecating)
